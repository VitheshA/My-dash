Time series: DatetimeIndex, slicing & rolling windows

What might trip you up
  • A DatetimeIndex is an index whose labels are dates/times, which lets pandas slice by calendar periods.
  • A rolling window uses the most recent N observations at each point; it is not a single average over the whole dataset.
  • `shift(1)` moves information by one observation. In a backtest it is commonly used to keep today's decision from seeing today's result.
Why this matters

Time carries information in markets, so dates and windows must be handled deliberately.

Prerequisites

DataFrames; indexing.

Core idea — explained in my own words

A rolling window uses nearby observations through time, while resampling changes the time frequency.

Price data is special because its index means something: order and spacing carry information. Once a DataFrame has a proper DatetimeIndex (yfinance gives you one for free), three superpowers switch on. Date slicing: df.loc["2024":] just works. Resampling: df.resample("ME").last() converts daily prices to month-end prices — you will use this exact line in the momentum backtest. Rolling windows: df["Close"].rolling(50).mean() computes a 50-day moving average, the workhorse of trend measurement.

The classic trend signal is the golden cross: the 50-day average crossing above the 200-day average (bullish); crossing below is a death cross. Whether it predicts anything is debated — but detecting a crossover in code teaches you rolling, shift, and boolean logic in one shot, which is exactly the toolkit backtesting needs.

The mental model that unlocks all of pandas: a Series is never bare values — it's values stapled to labels (the index). Comparing two columns pairs them by label and returns a new labeled True/False Series; putting that Series in brackets keeps the True-labeled rows; .index just reads the labels back out. Every pandas operation is "align by label, act, return a new labeled thing." And the crossover idea in one sentence: "is above" can be true 300 days in a row — a cross is only the day the answer changes — which is exactly what combining today's condition with ~ of its shifted sibling encodes.

NumPy under the hood: why there are no loops

What might trip you up
  • Shape describes an array's dimensions. Axis tells NumPy which dimension an operation should work across.
  • A boolean mask is an array of True/False values aligned with the original array.
  • Vectorization means applying an operation to an array as a whole instead of writing the loop yourself.
Why this matters

Many numerical finance calculations operate on entire arrays rather than one row at a time.

Prerequisites

Python sequences; basic arithmetic.

Core idea — explained in my own words

NumPy arrays let numerical operations act on whole collections of numbers efficiently and predictably.

Every time pandas compared two whole columns for you in one line, NumPy was the thing actually doing it. NumPy's one idea: the array — a block of numbers of a single type, stored contiguously, so math on the entire block runs in compiled C instead of a Python loop. That's called vectorization, and it's why array math is both hundreds of times faster than looping and harder to get wrong — there's no bookkeeping for you to fumble. pandas is NumPy wearing labels; statsmodels and scikit-learn are NumPy wearing math. Learn the substrate once and every library above it makes sense.

From here forward the track adopts the professional rule: zero for loops over rows of data. If you catch yourself writing one, stop and ask which array operation replaces it. (Loops over tickers making API calls are fine — that's I/O, not math.)

Returns math: prices lie, returns compare

What might trip you up
  • A price is a level; a return is a relative change.
  • Simple returns do not add cleanly through time; wealth compounds by multiplying 1+r.
  • Keep period units straight. Annualization is a transformation with assumptions about the number of periods.
Why this matters

Prices alone are not comparable across assets; returns put assets on a common percentage scale.

Prerequisites

A $900 stock moving $9 and a $30 stock moving $3 had very different days — which is why quants convert prices to returns immediately. df["Close"].pct_change() gives simple daily returns. Chain them with a cumulative product, (1 + r).cumprod(), and you get the growth of $1 — the fair way to compare any two assets on one chart regardless of price level.

Two more tools finish the kit. Annualization: volatility scales with the square root of time, so annual vol ≈ daily-return std × √252 (252 trading days). CAGR: (end_value / start_value) ** (1 / years) - 1 — the single growth rate that compounds to the same endpoint. You'll also meet log returns (np.log(p / p.shift(1))) which add across time instead of compounding; know they exist, use simple returns for now.

Two roads to the same returns. pandas: df["Close"].pct_change() — labels do the day-pairing for you. Raw NumPy: closes[1:] / closes[:-1] - 1 — closes[1:] is "today," closes[:-1] is "yesterday," and element-wise division pairs them by position. It's shift(1) in position clothing, using exactly the slicing you drilled in Module 04. Both roads must give identical numbers; the second stretch below makes you prove it.

Before you can score stocks with z-scores (next module) or test strategies with t-tests (Module 17), you need the idea underneath both: the distribution — the shape traced out when you histogram every daily return. The most famous shape is the normal distribution, the bell curve, fully described by just a mean and a standard deviation. You can't average a P/E of 18 with an ROE of 0.22 — different units, different scales, and P/E is better low while ROE is better high. Normalization fixes all three problems. The two workhorses:

  • Percentile rank — df["roe"].rank(pct=True) maps every value to 0–1 by position. Robust, ignores outliers, loses magnitude.

A backtest replays history under a rule: each month, hold X; measure what the portfolio would have been worth. Mechanically it's things you own already — resample to month-end, pct_change, cumprod. The hard part is that backtests default to lying, in three specific ways you must be able to name in an interview:

  • Lookahead bias — the rule uses information not yet available at decision time. Classic tell: computing this month's signal and this month's return from the same row. The fix is one shift(1): decide on last month's data, earn this month's return.
  • Survivorship bias — testing on today's index members means every bankrupt or delisted loser was quietly removed before you started. Results inflate. We accept this bias in our student project and disclose it in the README — knowing your data's flaw beats pretending it away.
  • Cost blindness — monthly rebalancing churns the book; at even ~10bps a trade, ignored costs flatter the strategy. We'll apply a simple haircut per rebalance.

Skill or luck? Hypothesis testing before you need it

What might trip you up
  • The null hypothesis is the baseline claim you test. A p-value asks how unusual your observed statistic would be if the null were true.
  • A p-value is not the probability that the null hypothesis is true.

Why this matters

Prerequisites

Core idea — explained in my own words

Your P4 backtest beat SPY (or didn't). The question a professional asks next is brutal and precise: could pure luck have produced this? Hypothesis testing is the machinery for answering it. You assume the boring world — the null hypothesis, "this strategy has no real edge; its true average excess return is zero" — and then ask how surprising your observed result would be if that boring world were true. That surprise level is the p-value: the probability of seeing a result at least this good by chance alone. Small p (convention: < 0.05) lets you say the result is statistically distinguishable from luck. It never proves skill; it only makes luck an uncomfortable explanation.

One more idea, and it's the one that will guard your whole future in this field: test enough random strategies and some will look brilliant. Ordinary least squares (OLS) fits the line that best explains an asset's excess returns using the factors. The equation you're estimating: r − rf = α + β·(Mkt−RF) + s·SMB + h·HML + ε. Why this matters

Root finding

Why this matters

Root finding is where the track first turns “the method gets closer” into a measurable law. Different algorithms shrink error at very different rates, and you will test those rates against Taylor-based predictions.

Prerequisites

Calculus BC: derivatives, tangent lines, Taylor expansion. New: root-finding iterations, convergence order, and why the derivative matters.

Core idea — explained in my own words

Bisection repeatedly halves a sign-changing interval. It is slow but has a strong guarantee. Newton uses the tangent line to jump toward the root and is usually much faster near a simple root. Secant approximates the derivative from two points, trading some reliability for not needing f′.

errornext ≈ C · errorpThe exponent p is convergence order. Larger p means faster local convergence.
What might trip you up
  • Bisection keeps a sign-changing bracket, Newton uses a tangent line, and secant approximates the derivative from two points.
  • Convergence order describes how fast the error shrinks; it is not the same as the number of correct decimal places.
  • Newton is especially sensitive to small derivatives and poor starting points.
  • Secant avoids an explicit derivative but gives up some of bisection's guarantees.

ODE solvers — the module that generates the question

Why this matters

ODE solvers are where numerical approximation meets time. You now advance a dynamical system repeatedly, which makes accumulated error and long-time behavior visible and creates the research question for P2.

Prerequisites

Calculus BC: Euler’s method, derivatives, Taylor ideas. Differential Equations: first-order ODEs. New: systems of ODEs, RK4 structure, conserved quantities.

Core idea — explained in my own words

Euler takes a tangent step. RK4 samples the derivative four times and combines those samples to cancel lower-order error terms.

A system such as x′=v, v′=−x has two state variables, so we represent the state as [x,v]. The oscillator is useful because its exact energy E=½(x²+v²) stays constant.

What might trip you up
  • Euler takes one tangent step. RK4 combines four slope estimates to cancel lower-order error terms.
  • A system ODE has a vector state such as [x,v] rather than one scalar y.
  • The oscillator is useful because the exact system conserves E = 1/2(x^2+v^2), giving you something structural to measure.

Stability regions

Why this matters

Stability answers what accuracy alone cannot: what happens to tiny errors when a numerical method repeats the same update many times? This is central for long simulations and stiff equations.

Prerequisites

M4–M6, exponentials, complex numbers. New: test equation, amplification factor, stability region, stiffness.

Core idea — explained in my own words

For the test equation y′=λy, a one-step method has the form yₙ₊₁=R(hλ)yₙ. R is the method’s amplification factor.

|R(hλ)| ≤ 1For a decaying exact solution, a numerical multiplier with magnitude above 1 can amplify errors.

For Euler, R(z)=1+z, which on the negative real axis gives h≤2/|λ|.

What might trip you up
  • R(z) is the numerical amplification factor for the test equation y'=lambda*y.
  • For a complex number, |R(z)| is its distance from the origin. Stability asks whether repeated updates amplify magnitude.
  • Stability and accuracy/order are different properties.

μ̂ = (1/N) Σ XᵢThe estimator is simply the average of sampled values.

Why this matters

Optimization changes the numerical question from estimating a value to searching for a good point. The tunable landscape lets you increase difficulty while keeping the true global minimum known.

Prerequisites

Core idea — explained in my own words

The gradient points toward steepest local increase, so gradient descent moves against it:

xnew = x − η∇f(x)η is the step size.

Your fα adds periodic structure to a quadratic bowl. Increasing α creates more local structure while keeping the origin as the global minimum.

  • alpha changes the landscape; it is not an optimizer setting.

Why this matters

Now randomness moves from estimation into search. You are testing whether stochastic search finds better solutions when algorithms receive comparable computational effort.

Prerequisites

Core idea — explained in my own words

Gradient descent follows local slope. Random restart changes starting points. Simulated annealing sometimes accepts worse moves to escape local traps.

P(accept worse move)=e−Δ/TAs T decreases, worse moves become less likely.

The cost comparison is an explicit modeling choice. An analytic gradient does not universally cost d+1 function evaluations; d+1 corresponds to one finite-difference cost model.

Advanced variant · strong Math intersection

Scientific ML / differentiable simulation

Why it is interesting

This is the strongest bridge between your Computational Mathematics and ML work. Instead of treating ML as a black box, you investigate whether a model can learn or approximate a dynamical system while respecting numerical structure.

Variants to explore
  • Neural ODEs: learn a continuous-time dynamical model from data.
  • Physics-informed neural networks: put differential-equation structure into the training objective.
  • Differentiable simulation: optimize parameters of a simulator through gradients.
  • Operator learning: learn mappings between functions or fields, a later-stage direction.
Prerequisite: do not start this until you are comfortable with gradients, loss functions, train/validation, and your Math ODE work. This is an advanced branch, not a foundation step.
Practice — no code first

  3. What does a gradient of a loss tell you?
Reveal answers
  1. ML estimates a rule from data; numerical analysis solves a specified mathematical problem using an algorithm.
  2. Structure can restrict implausible solutions and improve data efficiency or physical consistency.
  3. How the loss changes with the model parameters, giving a direction for optimization.

  2. The model violating the known structure, because the validation metric alone did not capture that failure.

Current open-source reality
